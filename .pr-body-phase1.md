## Summary

Phase 1 of the modernization plan (grilling session, 14 settled decisions). Re-architects the app so charts are driven by a shared declarative config instead of hardcoded error-domain code, and moves to a modern stack:

- **Monorepo (npm workspaces)**: `client` (new), `server` (TS gateway), `legacy` (isolated Vue 2 stack, kept alive until parity)
- **Client**: Vue 3 + Vite + TypeScript + Vuetify 3 + Pinia + ECharts, with a typed tRPC client (`AppRouter` imported type-only via `@server` alias)
- **Gateway**: tRPC v11 over Express — `health`, `sources.list`, `sources.series` (stub until adapters land in feat/02); Zod schemas for `Source`/`Panel`/`SeriesResponse`; config loader with `env:VAR` secret resolution
- **dashboard.config.json**: single source of truth (ndjson + REST sources with declarative mapping, 2 panels with refresh)
- **Domain docs**: `GLOSSARY.md` (8 terms) + ADRs 0001–0003 (gateway-adapters, config-driven, fresh-scaffold-over-strangler)

## Evidence it works

- vitest: **9/9 green** (env resolver, config loader, invalid fixtures)
- server `tsc --noEmit`: clean · client `vue-tsc + vite build`: green (152 KB gz)
- Legacy untouched: `GET /api/errors/data/years` → 200 · Gateway: `/trpc/health` → `{"ok":true}`
- Local run: `npm run dev:server` (:3000) + `npm run dev:client` (:5173, /trpc proxied)

## Merge danger

Two-way door with a caveat: `legacy/` moves the old stack into its own workspace (root scripts keep working), so the legacy app keeps running during phases 02–03. Full removal is planned for feat/04 once the new client reaches parity.
